Zyquo — macOS AI terminal agent

A native macOS AI terminal agent. Plan → execute → verify with safety gates, a premium TUI, persistent memory, a closed learning loop, and a real tool runtime (ZTP). Not a chat box with shell access — a genuine multi-step agent.

macOS 14+ Swift 6 · strict concurrency arm64 · x86_64 agent tools: shell · fs · git · ZTP×12 notarized · Developer ID Apache-2.0

Overview #

Zyquo is a terminal-first AI runtime for macOS, inspired by OpenHands, Cline, OpenCode, and Hermes — built Swift-native. Everything the agent does is renderable, reviewable, and reversible. It runs locally; your code and memory live on disk under .zyquo/ and ~/.zyquo/.

🤖 Real agent loop

Plan/execute/verify with stop conditions, retries, and replanning — not single-shot completion.

🛡️ Safety first

Rule-based risk classifier, approval gates (y/n/a/e/?), workspace boundary guard, trust scopes.

🎨 Premium TUI

"Premium Panels + Iris" — filled gradient cards, correct Unicode width, truecolor→mono degradation.

🧠 Closed learning loop

Persistent user model, skill extraction, self-improving skills, nudges (Hermes-inspired).

🔌 Real tool runtime

Native shell/file/git tools plus the full ZTP suite (12 tools).

🔑 Keychain-only secrets

API keys live in the macOS Keychain, never in shell history or files.

Quick start #

zyquo provider login anthropic --key sk-ant-...   # store key in Keychain
zyquo                                             # launch the interactive TUI
zyquo run "fix the failing tests and explain why" # agentic run (tools enabled)
zyquo ask  "explain this repo"                    # single-shot Q&A (no tools)
zyquo plan "add an auth flow"                     # plan only (no execution)

The agent runtime #

The zyquo run loop is a true multi-step agent:

intent → workspace scan → context assembly → planning → per step: tool proposal → risk classification → approval gate → execution → observation → verification → memory update → summarize → persist → learn
  • Planner → numbered, verifiable steps (each one tool call)
  • Executor → dispatches tool calls through a unified ToolRegistry with risk + approval gating
  • Verifier → pass / fail / unclear verdict per step
  • Stop conditions → max steps/cost, consecutive failures, loop detection, user cancel
  • Context assembler → workspace summary + project memory + user model + tool guidance, token-budgeted

Every state transition emits a UI event; nothing happens off-screen.

Tools #

The agent and interactive chat execute through one registry. Tool calls are typed and schema-validated — never eval of model output.

GroupTools
🐚 Shellshell.run — zsh, streamed, risk-classified, cancellable
📁 Filesystemfile.read · file.list · file.write · file.patch (unified-diff, boundary-checked)
🌿 Gitgit.status · git.diff · git.log · git.commit (never auto-pushes)
⚙️ ZTP ×12ztp.excel · docx · slides · chart · mail · message · browser · macos · ocr · notes · files · finder

ZTP tools are auto-discovered from the installed ztp binary and registered as ztp.*, so the agent can generate real Office documents and charts, send mail, run local OCR, read/write Apple Notes, manage files (search & compression), and drive Finder — all as part of a task.

Install/upgrade ztp ≥ 0.9.0 to expose all twelve tools to the agent.

Premium TUI #

The interactive surface uses a "Premium Panels + Iris" design language:

  • 🟦 Filled gradient cards — raised panels with iris (blue→violet) gradient titles and vivid rounded borders
  • 📐 Pixel-correct layout — DisplayWidth handles emoji / CJK / combining marks so panels never misalign
  • 🌈 Capability-aware — truecolor → 256 → 16 → monochrome, honoring NO_COLOR / CLICOLOR / TERM
  • ✍️ Streaming — token-by-token responses with an iris left-gutter; gradient hairline rules
  • 🎛️ 29 components — panels, diff view, spinners, progress bars, timeline, status badges, markdown renderer, modal picker, keymap overlay…
  • 🎨 5 themes — zyquo-dark (default), minimal, high-contrast, solarized-dark, plus user TOML themes

Closed learning loop & user model #

Inspired by Hermes Agent, Zyquo learns across sessions:

  • 🧑 Persistent user model — distills durable facts about you (stack, preferences, working style, constraints) with confidence reinforcement + decay; injected into planning. View with zyquo memory user or /whoami.
  • 🧪 Skill extraction — successful sessions become reviewable skill candidates (zyquo skills candidates / accept / reject).
  • 🔧 Self-improving skills — usage stats drive refinement proposals.
  • 🔔 Nudges — rule-based suggestions surfaced at session end (zyquo nudges, /nudges).
Nothing is auto-written: skills, refinements, and user-model changes are all proposed and require your explicit acceptance.

Memory & sessions #

  • Project memory — .zyquo/memory/project.md (hand-editable; agent proposes patches, never overwrites your notes).
  • Session memory — full transcript + tool calls, resumable across restarts and crashes.
  • Decision memory — append-only ADR-style log.
  • Retrieval — lexical (SQLite FTS) now; hybrid (FTS + embeddings) on the V2 path.
zyquo sessions                 # list sessions
zyquo sessions resume <id>      # restore plan, steps, context
zyquo memory                   # open the memory inspector

Providers & models #

Provider-agnostic with streaming and tool use. Keys are stored in the macOS Keychain (service dev.zyquo.cli).

ProviderNotes
AnthropicPrimary. Messages API, SSE streaming, native tool use.
OpenRouterCatalog passthrough + fallback routing.
Local (V2)llama.cpp / Apple Foundation Models on the roadmap.

A ModelRouter picks a model per task class (planning / coding / summarization / verification), overridable with --model.

Safety model #

  • Risk tiers — every command/tool call is classified SAFE / MODERATE / DANGEROUS / CRITICAL.
  • Approval gates — risky actions prompt [y]es / [n]o / [a]lways / [e]dit / [?]explain; trust is scoped (once / session / workspace / global).
  • Workspace boundary — writes and shell cwd stay inside the workspace unless explicitly approved.
  • No silent anything — no silent network calls, no silent writes (every write is a reversible patch), no secrets in logs.
Approval is consent: Zyquo will not override a user who explicitly trusts a CRITICAL action.

Configuration #

Precedence: CLI flag > env var > workspace .zyquo/config.json > ~/.zyquo/config.toml > defaults.

# ~/.zyquo/config.toml
[ui]
theme = "zyquo-dark"

[agent]
max_steps = 40
max_cost_usd = 5.00
auto_approve_safe = true

[providers]
default = "anthropic"

[learning]
enabled = true
user_model = true
